# EveryCent 中期检查 PPT 制作文档

本文档用于指导制作 EveryCent 智能记账系统中期检查 PPT。建议控制在 12-15 页，汇报时间 6-8 分钟，重点展示“做了什么、怎么做的、目前完成到什么程度、后续怎么推进”。

## 一、PPT整体定位

### 汇报目标

中期检查不是最终答辩，重点不是把所有细节讲完，而是证明项目已经形成可运行系统雏形，并且前端、后端、数据库、AI 模块之间已经开始集成。

### 推荐汇报主线

1. 项目要解决什么问题。
2. 系统整体架构是什么。
3. 当前已经实现哪些核心功能。
4. 前后端和数据库如何协作。
5. AI 记账与预算提醒体现了什么创新点。
6. 当前测试情况如何。
7. 后续还要完善什么。

### PPT风格建议

- 背景简洁，推荐白底或浅灰底。
- 每页只讲一个核心点。
- 多放系统截图，少放大段文字。
- 图表优先：架构图、模块图、流程图、数据库关系图、功能完成度表。
- 页面标题用结论式表达，例如“系统已完成核心记账闭环”，不要只写“功能展示”。

### 标题

- 家庭、情侣、监督等共享记账场景需要权限控制。

## 第4页：系统整体架构

### 标题

系统采用 JHipster 单体架构，内部按前后端和业务层解耦

### 内容

```text
React 前端
  页面交互 / 表单 / 图表 / 文件下载
        |
REST API + JWT
        |
Spring Boot 后端
  Controller / Service / Permission / DTO
        |
MySQL + Liquibase
  用户 / 账本 / 记录 / 标签 / 预算 / 通知
        |
LLM 模块
  自然语言解析 / 预算提醒生成 / 结果校验
```

### 配图建议

做一张四层架构图：前端层、接口层、业务层、数据与 AI 层。

### 讲稿提示

虽然项目是单体应用，但逻辑上划分清晰。前端负责交互，后端负责业务和权限，数据库通过 Liquibase 管理结构，AI 模块只作为辅助工具，结果仍由后端校验。

## 五、PPT制作注意事项

### 内容控制

- 每页最多 5 个 bullet。
- 技术接口不要堆太多，挑核心接口讲。
- 代码不要大段贴，除非老师特别要求。
- 截图要清晰，最好统一浏览器宽度和主题。

### 讲解重点

- 讲“为什么这样设计”，不要只念页面。
- 强调前后端联调已经完成的部分。
- 强调 AI 输出不会直接无校验入库。
- 强调数据库使用 Liquibase 管理，避免直接改已执行 changelog。

### 常见提问准备

#### Q1：AI 记账如何保证结果可靠？

回答要点：AI 只负责辅助解析，后端会校验金额、类型、标签、日期和权限，标签必须来自数据库白名单，不能直接写入非法数据。

#### Q2：如何保证用户只能访问自己的账本？

回答要点：后端在账本相关接口中通过当前登录用户和账本权限表进行校验，成员权限分为 OWNER、READ_WRITE、READ_ONLY。

#### Q3：为什么使用 JHipster 单体架构？

回答要点：课程项目阶段使用单体架构能降低部署复杂度，同时保留清晰分层，前端、后端、数据库和 AI 模块仍然按目录和职责解耦。

#### Q4：预算提醒如何生成？

回答要点：后端先计算预算使用情况，再把结构化预算状态交给 AI 生成提醒文案，最后经过校验并可保存为通知。

#### Q5：目前还有哪些未完成？

回答要点：设置项还可接入后端持久化，AI 场景需要更多样例验证，自动化测试和最终演示数据还要继续补充。
